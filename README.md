# 映川 v0.3.0 · 个人影视播放器

Mac原生应用：检索网络影视目录、选择集数、在软件内播放，并在播放过程中使用GPU增强画面。源码与实际应用都在本目录。

## 启动

双击 `dist/映川-v0.3.0.app`。当前安装包面向 Apple Silicon Mac，为本地签名版本；旧版 `dist/映川.app` 保留在原处，退出旧版后再打开新版。首页兼顾电影、国产剧和美剧，提供推荐关键词和近期搜索。点击作品，选择来源、线路和集数开始播放。也可以搜索其他作品，或从左下角导入影片/媒体链接。

左侧导航及底部打开入口支持整行点击，当前页面高亮显示，鼠标经过或按下时提供反馈。切换到待看、继续观看等页面再回到探索，会保留本次搜索、筛选与已加载结果；需要重新发现时可清空搜索框后搜索，或在媒体来源页选择“刷新发现页”。侧栏改动验证见[v0.2.5验收记录](docs/验收记录-v0.2.5.md)。

v0.3.0 重做播放页：画面铺满播放器，顶部只保留片名、返回、视听适配和选集；底部用单排大按钮承载播放、快退快进、时间、速度、字幕、画质、音量和全屏。选集默认收起，展开后有独立的线路、剧集和片源区；跳广告与柔化进入“更多播放设置”，自动跳过后的撤销按钮显示在画面顶部。窗口和全屏播放时顶部及底部控件都会随闲置淡出。见[v0.3.0验收记录](docs/验收记录-v0.3.0.md)。

v0.2.9 按片源适配杜比视界与杜比全景声：读取主清单声明、当前所选轨道格式和系统能力后分层显示，可播放的杜比视界/HDR 片源交给系统原生呈现，普通 SDR 片源继续走实时增强。广告识别复用增强路径已解码的当前帧，同时保留少量前方预读，以便在插播出现前确认区间；无法共用时使用独立解码。播放页新增“视听适配”面板，界面统一了配色、圆角、描边与动效令牌。见[v0.2.9验收记录](docs/验收记录-v0.2.9.md)。

v0.2.8 增加本地自动跳过插播广告（实验）：在本机读取前方视频帧，识别澳门新葡京类推广画面并跳过确认的主段。默认开启，当前版本可在“更多播放设置”关闭；跳过后可撤销。不需要DeepSeek或API密钥。见[v0.2.8验收记录](docs/验收记录-v0.2.8.md)。

v0.2.7 修复控制栏隐藏后被进度预览清理回调立即唤醒的问题，并让窗口模式的底部控制栏也支持自动隐藏。播放中约3秒无操作后淡出，操作时恢复；暂停、缓冲、菜单、进度预览和拖动期间保持可见。见[v0.2.7验收记录](docs/验收记录-v0.2.7.md)。

v0.2.6 增加 macOS“播放”菜单和快捷键说明；点击控制栏的播放时间或按 ⌘J 可精确跳转，支持秒数、分:秒、时:分:秒及小数秒，保持当前播放/暂停状态。⌘P 播放暂停，⌥⌘← / → 快退快进，⌘← / → 上一集下一集。倍速、字幕和音轨菜单显示当前选择。选集面板会定位当前集，查找及核对其他片源时显示阶段并支持取消。具体修复与验证范围见[v0.2.6验收记录](docs/验收记录-v0.2.6.md)。

- 播放：单击影片画面即可暂停/继续，双击只切换全屏；单击会等待系统双击间隔，避免双击时先暂停。拖动、点控件、右键、切集或失焦会取消尚未执行的画面单击。播放、快退快进与其他图标按钮使用约42–48点的命中区域；连续操作按最新播放意图与累计跳转目标处理。也可用空格暂停/继续，左右键前后10秒，上下键音量，F全屏，M静音；支持进度拖动、倍速、选集和下一集。音量、静音前音量、倍速、画质模式和自动连播偏好在本机保存；睡眠定时位于“更多播放设置”。
- 进度预览：鼠标停在进度条上，显示对应时间的画面缩略图；拖动时也可预览，松开后跳转。预览使用独立解码器，不改变主播放进度和声音。网络位置首次取帧可能需要等待，失败时明确显示暂不可用；不会展示上一位置的旧图。预览显示原始画面，不叠加外部字幕或广告柔化。
- 控制栏与全屏：窗口和全屏模式播放中约3秒无操作后，视频上的顶部与底部控件一同淡出；窗口中的选集侧栏若已展开则保留。F、双击画面或全屏按钮进入沉浸模式，选集侧栏隐藏，全屏闲置时也隐藏鼠标。两种模式均可通过移动鼠标或按键显示控件；普通按钮上静止悬停仍会自动隐藏，进度预览、拖动滑块、打开菜单、跳过通知、暂停、缓冲或报错时保持可见。Esc/F或退出按钮回到窗口模式。外部字幕独立显示，并按控制栏实际高度避让。
- 自动跳广告（实验）：每2秒取样分析前方45秒，使用macOS本地中文OCR；显著品牌与推广词连续出现且识别出结束边界，才跳过确认主段。底部28%及自定义字幕保护区不参与判定，角标和单独出现的品牌不触发。暂停、拖动、缓冲时停扫；手动拖进已识别区间视为回看，本次不再跳过。原视频和字幕文件保持原样，字幕继续使用原始时间轴。初次模型加载可能较慢，独立读取前方片段也会增加网络与解码负载；可以关闭。当前只验证了合成MP4和普通HLS样片，真实插播可能漏检、误判或保留边缘，不支持保证所有广告清除。
- 广告柔化：“更多播放设置”→“广告文字柔化”→“框选广告与字幕保护区”。视频暂停后，在真实画面里拖出广告矩形；绿色底部28%默认保护，可切换“保护字幕”额外框出顶部、中部或双语字幕。黄色为广告框，重叠保护区的框会被拒绝；新增保护区后若已有广告框变红，应先移除冲突框。点击“应用柔化”，支持最多6个广告框和6个附加保护框。可随时关闭显示原画面；换集、换源或重新打开影片时清空，重试同一影片保留。只是局部模糊，不是无痕删除或背景重建，此框选柔化功能不自动识别画面贴片。
- 字幕：播放控制区的字幕按钮可选择已有轨道，或导入UTF-8 SRT/VTT/ASS文本；外部字幕可调整时间。ASS文本会提取对白，不支持完整ASS样式/动画。
- 画质：播放页右下角的画质菜单切换“原片”“GPU清晰增强”“GPU增强至4K”“Apple AI超分”；从“更多播放设置”→“播放信息”查看实际源尺寸、输出尺寸和处理状态。
- 来源：内置电影天堂、非凡、如意、魔都、无尽共5个目录；可启停、检查目录连接及代表影片媒体、添加兼容HTTPS CMS JSON接口。打开聚合作品默认优先魔都，可在“媒体来源”修改优先来源；手动来源筛选与详情选择优先，停用/移除后不会继续自动选用。升级会补入新增内置来源，同时保留已停用或移除的旧来源。单次检索最多使用列表中的前24个启用来源；目录在线不代表每部影片可播放。
- 找片：同名同年份作品聚合为一个入口，在详情选择来源版本；保留不同年份、不同季的独立条目。支持来源/年份筛选、排序、逐来源加载更多，以及单来源分类目录浏览。
- 待看：海报或详情点收藏，加入“我的待看”，重启后保留；移除待看不影响历史。
- 换源：播放页打开右侧“选集”，点击“查找其他片源”，再选择显示来源名与季标题的候选。程序核对同季同集、检查媒体清单后在软件内切换，并在资源就绪后恢复进度，保留核对期间最新的播放/暂停选择。搜索、集目读取及清单检查分别显示阶段，可随时取消；取消核对后保留候选供重选。版本时长或剪辑可能不同，恢复位置受新时长限制，需核对画面并按需拖动；候选画质显示为未知，实际画质看播放信息。季数不明确、集名或编号不匹配时保留当前播放。
- 历史：默认展示每部作品最近一集，也可查看全部记录、单条移除；详情可直接续播，关闭再打开保留上下文。进度跟随实际来源版本，跨版本不会自动混用。
- 故障处理：准备、缓冲和定位显示不同提示；持续等待15秒后提供“重试当前集”和“查找其他片源”，由你选择处理方式。失败后按播放可重试，并保留续播目标、外部字幕与偏移；普通暂停时重试维持暂停。无效字幕作为独立提示显示，播放器仍可继续使用。已修复暂停时卡顿事件误显示缓冲、失败后未停止播放，以及片尾跳回中段时旧结束回调误触发下一集。

## 大陆网络与媒体连接

本轮把“目录在线”和“影片数据可读取”分开检测。来源页点击“检测媒体”会读取代表片名、同名详情、实际HLS和首分片前缀，显示阶段、样本、时间及失败原因；支持最多3个检查任务、排队和取消。结果仅保留在本次会话。手动媒体检查也可用于停用的来源，“检测全部媒体”仅检查已启用来源。

应用内检测会单独排除HTTP/HTTPS/SOCKS/PAC代理，但VPN路由、系统DNS仍可能影响结果。正常检索和播放仍遵循系统网络设置。页面会显示代理/隧道迹象，不能把HTTP代理排除或一次成功标为大陆免VPN认证。

2026-09-27另用物理网卡绑定+独立AliDNS解析进行了开发期探测，未修改系统设置：电影天堂、魔都的《怪奇物语第一季》样本通过搜索、详情、HLS和两段前缀读取；非凡详情超时、如意TLS错误、无尽搜索超时。公开大陆节点另测魔都该片子清单有258/270个HTTP 200，首分片有261/270个HTTP 200或206响应，三大运营商均有成功样本。因此默认优先尝试魔都，但既有来源仍可选择，不因一次失败自动停用。

这些是指定时间和指定影片的连接样本，未证明全国所有网络、所有剧集或整集持续播放。本机物理接口的出口所在地未独立核验。完整方法与数据见[大陆连接调研](docs/research/mainland-connectivity.md)和[物理接口样本报告](docs/validation/v0.2.2/direct-media-physical.md)。

## 杜比与 HDR 的适配方式

| 片源情况 | 实际处理 |
| --- | --- |
| 明确 Dolby Vision（`dvh1`/`dvhe` 或 `dvcC`/`dvvC` 配置） | 挂系统原生层，不叠加 8 位增强；不重建 item、不打断时钟 |
| 用户关闭「实时画质增强」 | 切回原片：摘除转换输出，系统直接输出片源画面，柔化同时停用 |
| 明确 HDR（PQ / HLG / BT.2020） | 同上，保留系统原生呈现 |
| 格式不可查的 HEVC、未知传输函数且色域非 709 | 保守走原生，不猜测为 SDR |
| 确认 SDR（709 传输函数与色域） | 进入现有实时增强，输出 10bit 广色域纹理 |
| 主清单声明了杜比版本 | 只说明来源提供它；是否正在播放以当前所选轨道为准 |
| `CHANNELS="16/JOC"` 音轨 | 记为全景声声明，保留原轨；双声道与普通多声道不会被标为全景声 |

播放控制栏的「画质增强」菜单提供**实时画质增强**开关（关闭即切回原片，摘除转换输出、停用去噪/锐化/放大与广告柔化，不重建播放）。**不做 HDR 增强**：杜比视界与 HDR 片源固定走系统原生呈现，实时增强只作用于 SDR 片源。改写像素会让杜比视界的逐帧动态元数据失效，所以这不是一个可切换的选项；面板里以固定说明呈现，没有对应的档位。

普通 HLS 的分辨率/色域变体不是可选择的 rendition，挑选权在系统手里（实测官方 Apple 杜比样本与非凡样本的 `loadMediaSelectionGroup(for: .visual)` 都返回 nil），应用无法把 HDR 片源切到 SDR，因此也不提供这种承诺。

各档位的实测差异见[v0.2.9验收记录](docs/验收记录-v0.2.9.md)第十节：4K 输出确实生成 3840×2160，边缘细节在显示缩放后仍优于原片与清晰增强，且不改变平均亮度。对已经干净的 1080p 片源，提升幅度偏细腻。偏好会保存在本机，旧存档默认开启增强。开关关闭时菜单仍可直接选档位——选任一增强档会同时把开关打开，所以选择永远不会被静默忽略；当前档位在菜单里带 ✓ 标记。

“视听适配”面板分别列出片源声明、当前所选视频与音频轨道、本机能力（系统是否允许 HDR、屏幕 EDR、输出设备）和实际决策。硬件支持不等于正在输出杜比：扬声器 DSP、房间校准与杜比认证未测量。本机独立探测进程的 `eligibleForHDRPlayback` 返回 `false`，与 v0.2.7 记录的应用内查询不同，两者都不证明当前片源正在以 HDR 输出。

## 播放失败时的错误码

播放页会按系统返回的错误码说明原因，不再把所有失败都写成“封装/编码不支持”：

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| -1008 | 来源暂时不提供媒体数据（网络或来源侧限制） | 重试、换线路，或在媒体来源页检查该来源 |
| -1009 | 网络连接断开 | 检查网络后重试 |
| -11828 | 系统不支持该封装或编码 | 更换片源线路 |
| -12889 | 系统媒体服务被重置（播放期间音频或显示设备变化常见） | 重试当前集即可重建播放链路 |
| 其他 / 网络域错误 | 按域区分网络与媒体问题 | 重试或在右侧“查找其他片源” |

网络来源起播依赖两条规则，均已加入静态校验（`scripts/validate-passive-media-inspection.sh`）：

- 应用代码只使用异步访问器（`loadTracks(withMediaType:)`、`loadMediaSelectionGroup`），不使用已废弃的同步 `AVAsset.tracks` / `.duration` / `.isPlayable`——同步访问器对网络 asset 会阻塞加载，实测会让非凡等来源报 -1008 而无法起播。
- 同一片源上并发的加载会互相抢连接，因此广告扫描会等主播放就绪并已推进后才打开自己的解码器；“视听适配”只读取播放器已经拿到的轨道信息，不再向同一地址重复请求。

## 广告识别如何复用播放解码

自动跳广告在增强路径运行时，优先使用播放中已经解码的当前帧（缩到 960×540 交本机 Vision 识别），避免在这个取样点重复解码。前方尚未播放的画面仍需独立预读，否则只能等广告播完才知道其完整区间。两条路径共用 OCR、分类、PTS 校验与区间规则；原片模式、杜比/HDR 原生路由或增强失败时由独立路径覆盖。普通 HTTP HLS 的前视取帧可能只取得部分有效时间点；证据不足时不会猜出广告区间。实测合成片源的增强与广告扫描同时运行，交出 9 帧、接收 4 帧，并在广告出现前识别出 16–26 秒插播；这不代表所有网络片源都能提前跳过。

## 画质模式的含义

| 模式 | 实际处理 |
| --- | --- |
| 原片 | 系统解码与原始画面 |
| GPU清晰增强 | Core Image/Metal去噪及温和锐化，保持源尺寸 |
| GPU增强至4K | 去噪、Lanczos等比例放大、锐化，实际生成最高UHD尺寸的画面；这是GPU修复/缩放，不是AI超分，也不证明原生4K细节 |
| Apple AI超分 | VideoToolbox实际神经网络处理，按设备和输入尺寸查询可用倍率；本机M4已测试720p×1.5到1080p，不支持的1080p输入会显示原因并回到原片 |

增强在播放中进行，不需要等待整集处理完，也不生成整集帧文件。软字幕最后绘制。默认流畅优先，持续超过帧预算或遇到未支持的HDR处理时明确回到原片。能处理4K像素不代表屏幕具备4K物理分辨率，也不代表还原了丢失细节。

## 构建和测试

开发机需要macOS15+和Swift工具链；Apple AI需要macOS26+及运行时能力支持。项目没有第三方包依赖。

```bash
bash scripts/swift.sh test
bash scripts/build-app.sh release
```

`scripts/swift.sh`会在`.build`中准备匹配的SwiftPM公开接口，解决此开发机CLT中残留的旧版private接口；不会修改系统工具链。最终.app只依赖macOS系统框架，不需要用户安装Python、FFmpeg或其他播放器。FFmpeg仅用于开发期媒体核验。

各版本的验证范围见验收记录；核心测试、GPU合成帧比较、原生窗口交互和完整影片观看分别记录。

诊断命令（运行播放测试时静音）：

```bash
dist/映川-v0.3.0.app/Contents/MacOS/Cinema --benchmark
dist/映川-v0.3.0.app/Contents/MacOS/Cinema --validate --seconds 1800 --title 怪奇物语 --mode upscale4K --report docs/validation/playback-report.json
```

- 该目录随时可能变化；影片供应许可未核验。官方平台网页不是通用媒体链接，本程序不登录会员账号、不提取浏览器凭证或绕过DRM。
- 核心播放采用AVFoundation。HLS、MP4等是否可播取决于实际编码；尚未集成libmpv，不能承诺MKV、所有音频编码和全格式字幕。
- 没有验证到三剧的原生4K来源；目前GPU4K路径可以改善显示效果，不能称为原生4K或AI4K。
- HDR 增强（把 SDR 转成 HDR 或改写杜比动态元数据）、多设备同步、完整 ASS 排版和通用 1080p→4K AI 模型尚未实现；本轮做的是按片源识别并保留原生杜比/HDR，不是转换。
- 未在实际杜比母版上核对动态元数据呈现、屏幕 EDR 效果或扬声器 Atmos 听感；官方 Apple 样本本轮只完成声明与变体读取，静音无窗口探测在 20 秒内未推进播放，因此不声称已播放杜比内容。
- 依赖子流的 `dec3` 布局在不同编码器间字段宽度不一致，本机一律保守判为未知，不排除会漏掉部分真实 Atmos 流。
