# 澄幕 v0.4 界面重设计

用户已选择深色观影与 B 站蓝，并要求重新设计全部界面、删除日常界面中的检查用语。实现继续使用现有 SwiftUI / AVPlayer，不更换播放引擎。

## 参考与边界

- B 站官方网页 https://www.bilibili.com/：搜索、分类、封面、标题依次分层；本次网页截图有翻译/登录浮层，因此不据此推断被遮挡部分的布局。
- 官方客户端下载页 https://app.bilibili.com/：2026-10-26 读取 HTML 及其 Mac 界面展示图 `https://i0.hdslb.com/bfs/activity-plat/static/20220518/49ddaeaba3a23f61a6d2695de40d45f0/jfh2rRs97W.png@1412w_908h_1c`。这是官方宣传图，不是当前客户端完整交互验收。可观察到紧凑侧栏、顶部导航、横向分类、以封面为主的内容网格，以及独立深色播放窗口。
- 当前 Mac 未安装 B 站客户端。官方下载安装链接及官网版本 API 返回的 v1.19.0 链接都返回 HTTP 403，未取得安装包、未进行反汇编、未取得或复制其源码。反汇编机器代码也不等于恢复原始工程源码。
- 蓝色 #00AEEC 来自网页品牌数据；炭黑背景、布局细节、SwiftUI 组件及占位封面为澄幕自己的设计。宣传图中的旧版粉色不作为本项目主色。不复制 B 站标识或应用素材。

## 实现方向

1. 炭黑底、安静分隔、蓝色仅用于选中和主要操作，减少通屏蓝色与堆叠卡片。
2. 探索优先展示内容；分类与筛选紧凑，取消占据大量空间的空白宣传横幅。
3. 卡片主信息为封面、片名和自然的画质标签；无封面时提供不同构图的文字封面，不伪造电影海报。
4. 详情集中呈现片名简介、播放/待看、来源与选集。日常文案使用“画质”“更新”“暂未获取”，不展示“抽样”“轨道读取”“验收”等开发用词。
5. 待看、观看历史、媒体来源、画质设置与播放界面使用同一间距、字体和操作反馈。连接诊断和详细处理信息可展开；影响实际播放的失败与回退仍需说明。
6. 画质来自指定来源某一集的实际读取，不将文件名、目录名称或标称 4K 当作检测结果，不将宽银幕 3840×1600 写成 2160p；详细尺寸及所对应集目可查看。

## 验证

使用真实 SwiftUI 渲染探索、最小窗口、搜索、详情、待看、历史、来源与画质设置。离线演示数据的说明保存在报告与截图外，产品界面不混入检查横幅。静态图片检查不等于鼠标交互或整集播放验收。另运行队列/缓存、核心逻辑与既有播放相关回归。
