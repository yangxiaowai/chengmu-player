# 实时修复的轻量内容自适应后处理候选

核查：2026-09-29；范围：Apple 时域处理之后、放大之前或最终显示之前的小型 Metal/CI 空间算子。已读 `restoration-papers-2026-09-28.md`，本轮不重复神经网络超分列表。以下仅文献、源码与成本分析；没有 GPU 测量、模型下载或生产代码修改。先使用 web-access 技能的依赖检查，再读取公开一手页面。没有使用登录站点或新建浏览器标签。

## 本轮选择

建议先比较 **CDEF 思路的受限去振铃** 与 **小半径自引导滤波**，只选一个清理阶段接入，不默认串联。二者均不增加未来帧等待，也不产生学习模型的虚构纹理，但仍可能损失真实弱纹理。**RCAS 只作为弱锐化对照**；它的噪声选项不是去噪器，不能用来直接解决用户已经看到的噪点。

现有 `DetailScaler` 已有 16-tap cubic、方向一致性门控和 2×2 包络夹紧；重复加全局锐化不解决压缩噪声根因。当前 `.restoration` 路径在时域后直接进入 AI/空间放大，所以应优先验证“源尺寸轻清理后再放大”，而非在 4K 上花四倍像素成本磨皮。这是基于当前代码的工程选择，不是原论文结论。

| 候选 | 本轮作用 | 可实现成本（非实测时延） | 主要风险 |
| --- | --- | --- | --- |
| CDEF-inspired 受限差分 | 边缘附近的低幅振铃/蚊噪 | 8×8 方向分析 pass；滤波 pass 每像素最多 12 个邻居加中心，无指数函数，无跨帧状态 | 编码强度未知；弱笔画和织物也可能被当作伪影；块间方向跳动 |
| 灰度自引导滤波 | 平坦暗部、轻噪声、温和细节保持 | 半径 1–2；融合后可用约 4 个全分辨率可分离 box pass，保留源尺寸；不是一 pass 算法 | ε 太大抹细节；自引导会保留强噪点；FP16 方差消减误差 |
| FSR 1 RCAS | 可选、低强度清晰度恢复对照 | 一 pass、十字 5 次纹理读取；RGB min/max 和少量倒数 | 不会移除噪声；抑噪开关也只减锐化，默认强度可能增噪 |

## 1. CDEF：只过滤“小而不可信”的差分

原始论文：Midtskogen、Valin，*The AV1 Constrained Directional Enhancement Filter (CDEF)*，2017 修订。它在 8×8 区域估计八个候选方向，沿主方向强一些、旁向弱一些地滤波；幅度大的差分逐渐失去权重，最后限制到邻域值域。原设计位于解码环路中，强度由编码器显式传输，并非只凭视频像素即可得到。论文给出的方向搜索复杂度是每个 8×8 块 376 次加法、124 次乘法及 7 次比较；不是整个滤波的成本。[原论文 §2–4](https://arxiv.org/pdf/1602.05975)

关键约束函数可写成（整数形式，`S=0` 时输出 0）：

```text
u = max(0, D - floor(log2(S)))
f(d; S,D) = sign(d) * min(abs(d), max(0, S - (abs(d) >> u)))
y = clamp(x + rounded(sum(w_j * f(x_j-x))/16), local_min, local_max)
```

VideoLAN 官方 dav1d 的 `constrain`、`cdef_filter_block_c` 和 `cdef_find_dir_c` 给出可核对实现：两组主方向距离共 4 个邻居、副方向共 8 个邻居，并在组合滤波结果上执行值域夹紧。代码文件和项目 COPYING 均列 BSD 2-Clause 条款。[官方实现](https://github.com/videolan/dav1d/blob/14c73c7db38eebfd3202146b76a1ad4df90dd3a2/src/cdef_tmpl.c)、[COPYING](https://github.com/videolan/dav1d/blob/master/COPYING)

**针对播放器的实验设计（本项目推断）：**

- 先在时域输出的源尺寸上执行；滤波从不可变输入读、写独立纹理。方向统计可在一个 8×8 threadgroup 内共享加载，不能每个输出像素重新做整块方向搜索。
- 我们拿不到编码器的 CDEF 强度、量化参数及 skip 标记，所以只能称“借鉴 CDEF 的后处理”。原版的编码效率增益不能外推成 H.264/HLS 二次后处理收益；已经有解码器去块/去振铃的源可能被重复处理。
- 从极弱 `S=2/255`、`4/255` 的 **SDR 编码亮度域**开始小网格对照，副方向强度更低或关闭；这些是待测参数，不是推荐上线默认值。若采用浮点连续约束，不带整数位移/舍入，必须标注它并非 AV1 位精确实现。
- 不要把源平面当作新的块边界检测器去强制“每 8 像素去块”：8×8 是方向分析窗口，非对当前素材真实编码分块位置的已知信息。
- 本轮更适合蚊噪/振铃，不保证消除明显宏块或恢复已经丢失的纹理。

Mozilla 作者团队的讲解也明确其目标是抑制编码伪影、保留方向性结构；其中历史 Daala 7-tap/5-tap 方案不应与最终组合 CDEF 混用。[作者团队说明](https://hacks.mozilla.org/2018/06/av1-next-generation-video-the-constrained-directional-enhancement-filter/)

## 2. 自引导滤波：平坦区收缩、强边缘少动

He、Sun、Tang 的 Guided Image Filtering 从窗口内局部线性模型推导系数；灰度自引导 `p=I=Y` 时简化为：

```text
mu = box(Y), variance = max(0, box(Y*Y) - mu*mu)
a = variance / (variance + epsilon)
b = (1-a) * mu
q = box(a) * Y + box(b)
```

`variance << ε` 时主要平滑，`variance >> ε` 时接近保留原值。完整算法必须平均系数，直接用每像素 `aY+b` 是另一种局部收缩，不能称原始 guided filter。论文的 O(N) 结论利用 box/integral-image 计算，并不自动等于 Metal 单 pass。[原论文 §3.1、3.2、3.6](https://people.csail.mit.edu/kaiming/publications/eccv10guidedfilter.pdf)

OpenCV 官方 `guided_filter.cpp` 可作 CPU 数值参照；源码使用 boxFilter、浮点工作类型并明确边界策略。该文件头仍是 BSD 3-Clause，仓库根为 Apache-2.0，不能只看仓库徽标丢掉文件声明。无需为了一个小滤波器把 OpenCV 打包进应用。[固定源码](https://github.com/opencv/opencv_contrib/blob/b603a10002b98a2f7d9132a0c8dc21fec3cc7339/modules/ximgproc/src/guided_filter.cpp)、[项目许可证](https://github.com/opencv/opencv_contrib/blob/4.x/LICENSE)

**针对播放器的实验设计（本项目推断）：**

- 半径先固定 1，再比较 2；只处理源尺寸亮度，不预缩小整幅输入。第一组横/竖 box 得到均值与二阶矩并融合 `a,b`，第二组横/竖 box 平均系数并输出，约四 pass；纹理带宽可能比算术更贵。
- 使用 `RG32Float` 计算均值/二阶矩/方差基线。中灰区域 `E[Y²]-E[Y]²` 相消后非常小，FP16 统计可能把真实弱纹理算成零方差；先验证 FP32，不能为了省内存先全改 half。
- `ε` 与强度单位平方相关。例如将编码亮度归一化到 0…1 后，测试 `(1/255)²…(4/255)²`；不能把 `2/255` 本身当 ε。参数仅用来构建候选对照，不能当作已验证的自动估计。
- 保留色度或以小幅亮度差修正 RGB，限制修正幅度和有效色域；不要用 `q/Y` 无保护除法，以免暗部色噪声被放大。
- 不采用全局“细节层×5”增强。若后续需要补回细节，先把残差限制在少量编码值内，并在噪点、高反差细笔画和字幕区禁用。

## 3. RCAS：低成本，但仅作有约束的锐化对照

AMD 官方 FSR 1 的 RCAS 是不缩放的五点十字滤波，输出为 `(m+w(n+e+s+w_neighbor))/(1+4w)`；负旁瓣系数由局部最大/最小值限制。`FSR_RCAS_DENOISE` 用归一化高通量减弱旁瓣系数，代码映射因子仍在 0.5…1；它不把输入的噪声滤掉。官方 sharpness 参数 **0 表示最强**，增大数值才按 stop 减弱，不能把“0”当关闭。[官方 shader 的 RCAS 部分](https://github.com/GPUOpen-Effects/FidelityFX-FSR/blob/a21ffb8f6c13233ba336352bdff293894c706575/ffx-fsr/ffx_fsr1.h)

本轮若比较，使用很弱强度并开启噪声抑制，放在完成清理与缩放之后；另用 `mix(original,rcas,amount)` 给真正的关闭状态。纹理读取只需中心及上下左右，但在 4K 上仍是额外全屏 pass，不能用 AMD 游戏 FPS 代替 M4 本机计时。由于我们处理的是影视压缩和胶片颗粒，不是干净的游戏抗锯齿输出，暂不列默认路径。选取的旧 FSR 1 仓库文件头及 `license.txt` 均为 MIT；不将该结论推广到所有新版本 FidelityFX SDK 文件。[该仓库许可证](https://github.com/GPUOpen-Effects/FidelityFX-FSR/blob/master/license.txt)

## 字幕、色彩与时域的共同约束

以下是本轮实现/验收建议，不是论文保证：

1. **外挂字幕最后合成。** 烧录字幕优先使用已知保护区：滤波半径范围内扩张保护，保护区保留处理前像素，边界在外侧平滑衔接。高对比检测不能识别所有弱灰字幕；必须测 1–2 像素斜笔画、白字黑描边与灰字。需要只做轻量保边时，方向高置信只能减少跨边缘混合，不能替代字幕保护区。
2. **清理强度与边缘强度分开。** 正常皮肤/细织物可有低对比真实纹理；不要简单地把“低方差”全部抹平。以受限最大改变量和保守关闭状态约束未知区域。
3. **域一致。** 当前管线使用线性 RGB 中间图、最终 sRGB 输出。CDEF 的原始整数阈值来自编码像素，RCAS 官方输入约束也接近显示编码域；不能把相同数字直接塞入线性 RGB。明确在哪个域统计、调整和夹紧，最后维持已有色彩输出契约；HDR/Dolby 继续原生直通。
4. **单帧自适应也会闪。** 块方向/阈值硬切换会随噪声改变。先用连续强度/低置信趋零；若新增时间平滑，只平滑参数，不混合无对齐旧像素，并沿用源切换/seek/切镜的重置规则。
5. **反锐化伪影回归。** 阶跃边缘必须量化 overshoot/undershoot，字幕测笔画连通与灰度误差；不能只看锐度评分。平区噪声下降却让头发/字幕糊掉，不算修复通过。

## 本轮最低可比较实验

先选 CDEF-inspired 与 guided 两个独立候选，保持现有缩放器不变。使用现有同一批源帧同时比较：当前时域输出、候选清理后、最终相同目标尺寸；不要因不同缩放尺寸让候选显得清楚。

- **质量**：无噪声控制片必须接近原值；已知压缩与噪声片分开测；记录平区噪声 MSE、边缘过冲、弱纹理损失、字幕误差。真实低码率人物/暗场/快速剪辑进行盲看。
- **时间**：源尺寸 720p/1080p，预热后完整 command 完成 P50/P95/P99，再跑带 AVPlayer 的完整管线；仅局部 kernel 快不能证明播放可实时。60 fps 插帧现有真实预算已紧，不自动将此额外处理加入插帧预设。
- **参数**：每候选先 2–3 个温和强度，失败原因是噪声仍在、纹理损伤、文字损伤还是过预算；不无限搜索参数，也不默认叠满全部算法。
