# 映川 v0.2 日常观看体验建议

调研日期：2026-09-27。范围：只读检查 v0.1 的 `AppModel.swift`、`ContentView.swift`、`PlayerView.swift`、`PlaybackController.swift`、`SettingsViews.swift`、`README.md`，并核对 IINA、Jellyfin、mpv 的官方文档/源码。文中代码行号对应本次检查时的 v0.1 快照，后续实施会移动。未修改产品代码；这是静态检查与设计建议，不是原生应用运行验收。

本轮优先解决三个连续动作：找到同一作品的可用版本，第二天准确接着看，播放出错后保留已有配置继续看。新增来源只有配合这些流程，才会成为有效选择。

## 官方产品给出的具体参考

| --- | --- | --- |

| IINA 播放界面与偏好 | 官网列出鼠标/触控板手势、缩略图预览、系统媒体控制；偏好源码有单击/双击动作、控制栏自动隐藏、音量、恢复上次位置 | 本轮先做确定的基础手势、提示及偏好；缩略图、画中画属于后续扩展。[官网](https://iina.io/)、[偏好源码](https://github.com/iina/iina/blob/develop/iina/Preference.swift) |
| mpv 键盘与语言偏好 | 提供跳转、倍速、暂停等键盘操作，以及优先音频/字幕语言列表 | 快捷键要有可见反馈；换集选择音轨时以语言语义匹配，不能复用上一集的轨道索引。[官方快捷键](https://mpv.io/manual/stable/#keyboard-control)、[轨道选择](https://mpv.io/manual/stable/#track-selection) |

以下八项为基于上述材料和现有代码提出的设计判断，不代表这些产品提供了相同实现，也不要求引入它们的播放器或服务端。

## 本轮八项可落地改进

### 1. P0：同作品多来源聚合，保留版本身份

**痛点。** 增加来源后，同一季会出现多张近似海报；用户要反复打开详情才知道哪些可播。当前 `AppModel.swift:71-86` 只按 `providerID:id` 去重，`ContentView.swift:131-134` 原样画出目录结果。

**最小实现。** 新增一个显示用分组模型，保留每个原始 `MediaTitle`；卡片展示“3 个来源”，详情选择来源后才加载线路。优先使用明确的标准化标题、明确季数、兼容年份分组；重名不同年份、不同季、电影剪辑版或信息不足时保持分开。“疑似同作”不能自动恢复别的来源进度。已有同季同集核对逻辑继续用来保护播放切换。

**验收。** 三来源同一明确季标题显示一张卡、三条可选来源；同名不同年份和不同季保持独立；原始来源信息可见；切换失败不丢当前播放。

**工作量。** 中，集中在 AppModel 的派生列表与 ContentView 卡片/详情，不需要改播放器内核。

### 2. P0：继续观看以作品最近一集为主，详情直接续播

**痛点。** 当前 `ContentView.swift:139-154` 每集一行；看过一季后难找其他作品；详情 `:197` 固定从第一集开始。每次回片库都要自己找上次看到哪一集。

**最小实现。** 保留完整历史，首页/继续观看优先展示每个可确认作品/季最近观看的一集，行内明确“第 N 集 · 12:34”。详情主按钮根据当前作品现有记录变为“继续第 N 集”，另保留“从头播放”；集数按钮用进度/已看标签。提供单条删除及“全部记录”切换；已完成记录仍留在全部记录中。跨来源分组只合并展示，续播必须调用实际记录所属版本。

**验收。** 看三集后默认列表只有一个该季入口；第二天从最近一集原位置续播；切换来源不会将另一剪辑版的秒数直接当成原进度；单条删除不影响其他集。

**工作量。** 中。沿用 `WatchRecord.playbackContext`；不重构已有历史文件的必要字段，不丢旧数据。

### 3. P0：重试保留字幕与位置，错误给出下一步

**痛点。** 一次网络中断之后，用户已导入的字幕和调好的偏移会丢失；旧播放地址失效时“重试”仍只重放同一旧 URL。当前 `PlaybackController.swift:167-169` 调用 `open`，`:79-81` 清空字幕与轨道状态；`AppModel.swift:122-132` 用历史里的 URL 直接打开。

**最小实现。** 把“重试当前媒体”与“打开不同媒体”的状态清理分开；同 URL 重试保存外部字幕、偏移、语义音轨选择、倍速、位置和播放/暂停意图。错误卡展示简短原因、当前来源、“重试当前集”“重新读取目录”“查找其他来源”。目录刷新必须核对同作品/季/集后再更换 URL。缓冲长时间无进展时提供可操作提示，不无限静默旋转。字幕导入失败用独立提示，不占用致命播放错误面板。

**验收。** 导入字幕并偏移 1.5 秒后重试，字幕和偏移仍在、位置未归零；暂停状态下重试不意外自动播放；目录变更或目标集缺失时保留原上下文并明确报告；字幕文件无效不建议重启影片。

**工作量。** 中。优先修复同 URL 重试保留状态和字幕错误分类，目录刷新作为第二小步。

### 4. P1：本机“想看/收藏”，与观看历史分开

**痛点。** 搜索到电影暂时不看，下一次只能重搜；现有 `AppSection` 与 AppModel 只有历史，没有书签入口。

**最小实现。** 海报和详情增加收藏按钮，侧栏增加“我的收藏”；存储作品标识及必要目录元数据，打开收藏时刷新详情。取消收藏不删历史；收藏条目来源移除或失效时仍保留标题，可重新搜索。首版采用本机持久化，无需账号或同步服务。

**验收。** 收藏后重启仍在；取消收藏不影响进度；来源失效时条目仍能找到、能够重新检索。

**工作量。** 小到中。收藏可先按来源条目保存，聚合显示成熟后再增加确定的作品级去重。

### 5. P1：搜索筛选、稳定排序和明确的加载更多

**痛点。** 搜“火线”时当前用硬编码关键词替换 `AppModel.swift:67-69` 避开第一页噪声。界面 `ContentView.swift:120-135` 没有年份/来源筛选，也没有后续结果入口。用户无法判断“没找到”还是“尚未加载”。

**最小实现。** 首版仅使用已有可信字段：来源、年份；排序提供相关度、年份新到旧、片名。默认先排完整标题匹配，其次前缀，再包含；排序必须稳定，不能以请求完成次序作为用户可见顺序。分页按每个来源分别记录页号、结束状态、错误，点击“加载更多”只访问仍有下一页的来源；新查询取消旧分页。客户端筛选标明“在已加载结果中筛选”。没有接口页数证据时不显示“全部”。

**验收。** 同一次搜索重复执行，相同输入结果顺序稳定；第一页没有的明确条目可通过后续页发现；一个来源翻页失败不清空其他来源；切查询不会混入旧结果；不同来源页大小不同仍不重复。

**工作量。** 中；若本轮核心服务没有可靠分页元数据，先交付筛选/稳定排序，分页单独记录为未完成，不能用本地数组分段冒充远端翻页。

### 6. P1：保存少量高频播放偏好，音量静音可恢复

**痛点。** 每次重启自动下一集恢复为开，倍速/音量/增强恢复默认；静音后取消静音一律跳到 80%。代码在 `AppModel.swift:30`、`PlaybackController.swift:21-24`、`PlayerView.swift:48`。

**最小实现。** UserDefaults 保存自动下一集、音量、默认倍速、增强模式、选集栏状态；音量与 mute 独立，取消静音恢复原音量。字幕/音轨优先语言作为可选增量，通过语言/名称匹配新媒体轨道，不保存易变的数字索引。字幕偏移先限定到单集/单版本，避免错误应用到整部剧。

**验收。** 25% 音量静音再恢复仍为 25%；重启保持自动下一集关闭和选定增强模式；新的媒体缺少首选语言时能回退；未知/非法保存值回到有效默认值。

**工作量。** 小。需区分用户选择的增强模式与运行时回退到原片，后者不应覆盖用户偏好。

### 7. P1：播放界面的键盘可达与简洁反馈

**痛点。** 现有快捷键只有空格、左右、F、M；`PlayerView.swift:34` 只定义双击全屏，`:44-49` 未显式申请初始焦点；看电影时底部控制栏和右侧选集长期占画面，操作后也没有统一反馈。

**最小实现。** 进入播放器显式聚焦，文本输入或弹窗活跃时不截获字符键；单击画面播放/暂停与双击全屏采用互斥识别。保留当前快捷键，再加上下音量、Esc 退出全屏、可见快捷键帮助；快进、音量和倍速显示短暂画面提示。全屏时控制栏在闲置后隐藏，鼠标移动、暂停、错误、菜单打开时显示；选集关闭状态记忆。下一集不存在时禁用按钮并显示原因。

**验收。** 进入播放无需先点画面即可空格暂停；点过滑条/菜单后快捷键仍正确；双击不多切一次暂停；全屏操作可找回控制栏；无下一集按钮不再空操作。

**工作量。** 中。焦点与手势属于原生 UI 行为，必须在实际应用中验收，静态单测不能证明键盘可用。

### 8. P1：来源状态可解释，删除/停用能稳定保存

**痛点。** 设置只有启停和删除，不知道哪个来源慢或不可用；全部删除后重启会默默恢复默认来源。当前 `AppModel.swift:52` 拒绝载入合法的空数组，`:250` 又允许删空；来源显示见 `SettingsViews.swift:38-45`。

**最小实现。** 正确区分“没有保存过配置”与“用户保存了空列表”；给每个来源显示上次检索结果、时间、响应耗时和本次返回数量。添加接口后进行目录格式探测并报告状态，支持单来源重试；空来源列表显示添加/恢复默认入口，不自动替用户开启网络来源。更改来源时取消进行中的旧查询，或明确标明结果来自查询开始时的来源集合。

**验收。** 删掉全部来源并重启仍为空；恢复默认必须由用户点按钮；一个来源失败不遮挡可用结果；禁用来源后不能误以为正在展示的旧结果来自当前启用集合。

**工作量。** 小到中；先修复空列表持久化，再添加服务层健康状态。

## 实施顺序与范围边界

建议顺序：先修复空来源列表、静音恢复和重试字幕丢失；再完成聚合卡片、继续观看/详情续播与收藏；随后补持久化偏好、筛选/排序、播放快捷键的原生验收；远端分页依接口能力落地。

本轮保留 AVFoundation 播放内核和现有 GPU 增强流程。libmpv、全格式字幕、缩略图生成、画中画、跨设备同步会扩大依赖与验证面，适合独立版本。来源数量、CMS 目录可达、HLS 清单可读均不等于实际可解码、内容身份正确、字幕同步或整集观看可靠。实现时沿用 README 对这些证据层级的区分。

上述缺陷来自可见代码路径；本次未运行 App 复现网络断流、键盘焦点、原生全屏或整集播放。源代码链接使用官方滚动分支/文档，后续版本可能变化，实施时应以本地代码和当次运行证据为准。
