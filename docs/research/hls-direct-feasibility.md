# HLS 直连：可行性与当前边界

> 本文记录 v0.4.6 build29 的前期可行性研究。当时的实验并未接入播放器；后续 build30 已加入有限条件下的 HLS 回环中继，具体支持范围和验证情况以 [v0.4.6 验证记录](../验收记录-v0.4.6.md)为准。

## 为什么 HLS 不直接复用 MP4 的直连加载器

Apple 工程师在 [AVAssetResourceLoader 讨论](https://developer.apple.com/forums/thread/113063)中说明，AVPlayer 需要通过 HTTP 获取 HLS 媒体分片，不接受像普通文件那样由资源加载器直接返回分片数据；后续回复明确这一限制也覆盖 fMP4 和 WebVTT 等分片。因此，仅对主清单发起无代理请求并不代表后续视频、音轨或字幕分片也已直连。

[HLSCachingReverseProxyServer](https://github.com/StyleShare/HLSCachingReverseProxyServer) 展示了将清单及分片请求引向本机 HTTP 中继的架构。它的示例不能直接证明适用于澄幕的认证、字幕、加密、Range、网络回退与隔离要求；澄幕没有把该项目作为依赖或直接引入其实现。

## 可复现的隔离概念验证

仓库包含一个**固定测试资源专用**的实验脚本，需在 macOS 和用户指定的 conda 环境下执行；需要 FFmpeg、OpenSSL 与 Xcode Command Line Tools：

```bash
conda run -n searchformoney --no-capture-output bash scripts/validate-hls-direct-feasibility.sh
```

脚本只在临时目录生成测试视频、英文 WebVTT 和随机测试密钥，启动绑定回环地址的两个临时服务。实验中继只认识这组固定文件名；测试后清理临时文件和密钥，不访问用户影片或外部媒体。

本机一次运行中，以下三组测试均由真实 AVPlayer 解码到视频帧、收到 WebVTT 字幕、跳转至 5 秒并再次取得帧：

1. 明文 HLS 片段；
2. 使用脚本临时生成密钥的 AES-128 测试片段；
3. 使用 `EXT-X-BYTERANGE` 的单文件测试片段，测试源观察到 8 次 Range 请求。

默认报告写入 `.build/hls-direct-feasibility.json`，不包含媒体密钥或随机本地访问令牌。AES 用于验证自制测试数据的普通 HLS 加密流程，不验证受保护商业内容，不涉及绕过 DRM。

**这不是生产中继。**实验服务将生成的短分片读入内存，不能用于长片。它没有证明自适应码率、动态清单、所有 URI 属性、多音轨、所有字幕格式、生产网络的反压与并发、Range 错误、取消、跨域重定向、cookie/认证、签名、FairPlay、代理策略或失败回退。不能将实验结果描述为 HLS 已直连、完整播放已验证或可保证大陆可达。

## 实际网络上的一次有限对照

在本机现有网络下，对三个目录中同一作品各取一个 HLS 地址，分别用禁用 HTTP 代理的请求和系统网络请求读取清单；其中一个地址的清单及首段前 4096 字节两种路径均读取成功，另两个地址两种路径均因服务端证书验证失败。未绕过 TLS 验证。该记录没有保存到仓库的媒体链接或媒体内容；它是一次有限读取，不是完整播放、平均延迟比较或大陆网络认证。

## 后续接入的必要条件

- 本机中继仅限回环地址，使用不可预测的短期访问令牌；资源由已验证清单授权，不能变成任意 URL 代理。
- 保持清单、片段、字节范围、字幕、替代音轨与加密方法的语义；不支持、无法核对或受保护的内容保守回退原系统路径，不能自行修改平台的认证与 DRM。
- 使用有界的流式读写、并发和内存管理；客户端取消、切片和关闭时按请求精确中断并释放资源。
- 保留证书验证及认证隔离；签名 URL、cookie、跨域和重定向需要针对性验证，不应静默改变播放权限。
- 基于真实 AVPlayer 做代理开关对照和首播、seek、断网、回退、快速切源、字幕、音轨、加密及长片测试；完整保留用户进度和播放/暂停意图。

在上述实现和验证完成之前，澄幕的 HLS 播放仍遵循系统网络设置。VPN 和 DNS 路由也不由 HTTP 代理设置决定。
