# v0.3.3 细节缩放接入只读审阅

范围：审阅 `DetailScaler.swift`、`EnhancementPipeline.swift` 的生产接入差异，以及 `VideoSurface.swift`、`PlayerView.swift`、实时画质设计说明中的相关约束。此次审阅没有编译、运行测试或运行 GPU。

## 源码结论

未发现阻塞性接入错误；这不等同于运行时验收通过。

- 颜色链保持一致：Core Image 将输入写为 linear RGBA16F，shader 显式编码为 sRGB，输出格式为 BGRA8Unorm；显示路径继续按 sRGB 解释纹理。没有引入额外的 shader 上下翻转。
- 输入纹理由串行增强 worker 复用，管线等待 command 完成后才返回结果；输出纹理每帧独立分配，避免覆盖正在显示的帧。现有单帧在途、迟帧丢弃、帧预算回退仍保留。
- `restoration` 在实际 AI 输出尺寸的基础上计算 4K 目标；已达到或超过目标边界的画面不再进入细节缩放。标签保留实际 Apple AI 倍率，并将后续空间插值明确标为“非 AI”。
- HDR/杜比原生呈现门禁没有绕过；局部柔化在基础纹理完成后执行有界复制。外置字幕在独立 SwiftUI 覆盖层，未进入缩放 shader。

## 仍需实际验收

最终上下方向、颜色和显示结果需要通过真实 `VideoSurface` 呈现验证。原型 PNG 的额外读回翻转约定不能单独证明最终界面方向正确。烧录字幕还需检查边缘、过冲和运动中的稳定性；真实播放还需验证完整处理链的完成时间、迟帧与回退表现。

旧原型 `probe.log` 不作为本版性能证据。本审阅不引用尚未查看的组合测试、独立计时或 UI 结果，也不据空间缩放内核的独立计时推断整条管线的播放帧率。
