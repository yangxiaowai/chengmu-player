# 3×3 受限亮度差分：CPU 候选（2026-09-29）

结论：**有可测但很小的局部收益，不能默认接入。** 当前真实生产时域输出后，中等强度 S=4 的 RGB PSNR 增益为压缩 +0.00594 dB、轻噪 +0.01199 dB、重噪 +0.05965 dB。相同候选会损伤极弱灰字和低对比细纹理：2 码对比的 1 px 灰字阈值召回 94.59%，幅度 2 码/周期 4 px 纹理仅剩 72.50% 调制度。这些损伤比整帧 PSNR 的微小改善更值得注意。

仅为借鉴 CDEF 约束函数的自写浮点空间后处理；**不是完整 CDEF、不是 AV1 位精确实现、不是 AI、没有锐化**。没有改生产文件、没有模型安装、没有 GPU 执行。阈值仅为事先指定的 2/4/6 码三档，没有额外扫参。

## 数学与边界

所有统计在 SDR **编码 RGB** 的亮度代理 `Y = 0.2126 R + 0.7152 G + 0.0722 B` 上完成，使用 0…255 码值单位。它是编码域亮度代理，不是线性光亮度，也不等价于 AV1 解码平面 Y。

取 3×3 的八个邻居。上下左右权重 2，四个对角权重 1；分母 16，相当于保留中心 4 的权重。

```text
φ(d,S) = sign(d) min(|d|, max(0, S − |d|/2))
cost[k] = |Y[k−]−Y| + |Y[k+]−Y|    # 四组对向邻居
cmin = min(cost), cmax = max(cost)
coherence = (cmax−cmin)/(cmax+cmin+S)
g = (1−0.9 coherence) (1−smoothstep(12,32,cmax))
Δ = clamp(g Σ w[j] φ(Y[j]−Y,S) / 16, −2,+2)
Q = clamp(Y+Δ, 3×3_min_including_center, 3×3_max_including_center)
RGB′ = RGB + (Q−Y)
```

- 大于等于 `2S` 的邻居差分贡献归零；连续方向一致性门控减轻线/纹理方向的平滑；强边缘门控归零。
- 不含块方向搜索、整数 damping、编码器强度、跨帧状态或未来帧。方向门控不是可靠字幕识别。
- 数学上亮度改变量 ≤2/255，float32 回算亮度的测试容差为 0.0001 码。已观测最大 2.000031 码来自浮点回算误差，不是放宽滤波上限。
- 边界复制。输入不可变，输出独立。已知保护区可以将 `Δ=0`；合成测试把字幕掩码扩张 1 px 后保持完全相同。无法自动知道所有烧录字幕区域。
- 输出显示裁剪对基线、候选和参考完全相同。当前时域浮点输出存在负值及 >1 值，例如第 24 帧最低约 −0.10、最高约 1.06。不能仅对候选 clamp 后就宣称滤波获益。报告同时保留“共同裁剪”和“双方均不裁剪”的结果。

## 真实生产时域输出对照

输入由父任务使用当前生产 `TemporalRestorer` 顺序处理后保存。480×200、float32 RGBA、小端、编码 RGB；评分排除 alpha，不增加 8 bit 量化。帧号固定为 12、24、48、72、84；来自同一段影片的三种退化，不能称三部独立影片。参考是同 PTS 干净片由生产 CI Lanczos 一次缩至 480×200 的浮点图。

下表以所有五帧 RGB 平方误差汇总后计算 PSNR；不是逐帧 dB 的算术平均。都在源尺寸比较，尚未通过最终生产放大器或播放器。

| 时域后输入 | 当前基线 PSNR dB | S2 增益 dB | S4 增益 dB | S6 增益 dB | S4 亮度 MSE 降幅 |
|---|---:|---:|---:|---:|---:|
| compressed-film | 31.481456 | +0.002353 | +0.005944 | +0.008363 | 0.273% |
| noisy-film | 32.246977 | +0.005346 | +0.011991 | +0.014552 | 0.564% |
| heavy-noisy-film | 33.608297 | +0.023994 | +0.059652 | +0.084503 | 2.406% |

两边都不裁剪的扩展范围 S4 PSNR 增益分别 +0.006187 / +0.011914 / +0.055745 dB，方向一致。共同裁剪 S4 的 15 个逐帧增益均为正，但重噪第 84 帧增益 +0.492 dB，而前 3 帧只有 +0.020…0.026 dB；收益明显依赖内容。

对同批生产原始解码帧（尚未时域处理）直接应用 S4，增益分别 +0.005956 / +0.009911 / +0.054333 dB。因此本轮没有证明此算子专门解决了时域残噪；也没有证明它优于更多时域样本或其他候选。

独立 FFmpeg RGB 解码 + Pillow Lanczos 参考的五帧 S4 增益为 +0.011441 / +0.018912 / +0.095190 dB；既有第 24 帧 PNG 两例分别 +0.011228 / +0.013336 dB。不同解码/缩小/量化路径的绝对 PSNR 不应横向混用；优先使用上表当前生产浮点路径。干净影片控制 S4 亮度 MSE 为 0.037251 码²，说明该操作即使无退化也不是完全恒等。

## 合成控制

使用固定 NumPy 随机种子 29092026。平坦区灰度为 16、64、128、192；噪声在编码亮度域，σ 为 2/4/8 码。这里只改变亮度，未声称去除独立色度噪点。

| 输入 | S2 | S4 | S6 |
|---|---:|---:|---:|
| σ2 平区 MSE 降幅（四灰度范围） | 11.18–11.48% | 42.29–42.81% | 62.63–63.10% |
| σ4 平区 MSE 降幅 | 1.42–1.49% | 9.23–9.64% | 21.12–21.90% |
| σ8 平区 MSE 降幅 | 0.06% | 0.45–0.47% | 1.31–1.39% |
| 干净幅度2/周期4 px 纹理调制度保留 | 90.00% | 72.50% | 68.00% |
| 干净幅度2/周期2 px 纹理调制度保留 | 100% | 80.00% | 51.43% |
| 2 码对比 1 px 灰字召回 | 100% | 94.59% | 94.59% |
| 2 码对比灰字最大笔画误差（码） | 0.533 | 1.128 | 1.169 |
| 白字 / 32 码对比灰字最大误差 | 0 | 0 | 0 |

灰字由固定的 1 px 横竖和对角 H/X 形笔画组成，共 148 个前景像素；召回阈值是原始对比的一半。S4/S6 各丢失 8 个弱灰前景像素，没有新增错误前景。它不是 OCR 可读性测试。S4 对 4 码对比灰字的最大误差仍为 1.066 码，即使二值召回是 100%，也不能据此说字形毫无损伤。

清洁常量图精确恒等；64→192 强阶跃精确恒等，无 overshoot/undershoot。人为边缘振铃夹具 MSE 为 0.6875 码²，S2/S4/S6 后为 0.683483/0.653066/0.598819；说明强边缘保护同时限制其最邻近振铃的清理能力。已知区域掩码扩张 1 px 后上述字形完全恒等，但未知灰字的风险仍在。

## 成本和未验证项

概念上可由单 pass 完成，每像素 9 个不同亮度采样、8 个受限差分、4 个对向成本，无指数函数、无历史纹理。实际 RGB 输入需要对应采样并计算亮度；这不是已经实现/计时的 GPU shader。

本次 NumPy CPU 全数组实现包含临时数组分配与边缘处理；预热 2 次后 7 次采样：

| 尺寸 | 中位数 ms | P95 ms |
|---|---:|---:|
| 480×200 | 4.140 | 4.196 |
| 1280×720 | 41.452 | 41.800 |
| 1920×1080 | 101.566 | 104.695 |

仅为 CPU 亮度滤波，不含 RGB 变换、解码、放大、GPU 同步或播放，且非独占系统。CPU 实现本身不足以满足 1080p 实时预算。不能将其比例外推成 Metal 时间，也不能据 9 taps 就断言完整播放器实时。没有测全 96 帧、时间差/闪烁、最终放大后评分、长视频、真实字幕 OCR、HDR、4K 或 AVPlayer 完整成本。

## 复现与产物

```sh
python3 .build/repair-v036/constrained/probe.py > .build/repair-v036/constrained/run.log 2>&1
```

- `probe.py`：唯一候选及全部夹具；仅 NumPy/Pillow/FFmpeg CPU，无安装动作。
- `results.json`：完整数值、输入 MP4 哈希、逐帧增益、三档参数、字幕/纹理/平区控制、时间样本。
- `run.log`：完成输出；当前运行正常退出，有限值/范围/恒定图/已知保护区断言通过。
- `*-production-temporal-frame024-{before,s4}.png`：生产时域后同帧 8 bit 展示图；评分仍使用原 float32 数据。

建议保留为被量化否决的默认候选，而非据微小 PSNR 增益自动接入。若继续研究，应先解决未知弱灰细字/周期纹理保护与内容泛化，再考虑 GPU 实现；本轮不扩大参数搜索。
