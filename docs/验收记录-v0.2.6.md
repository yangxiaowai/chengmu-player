# 映川 v0.2.6 验收记录

日期：2026-09-27。版本 0.2.6 / build 8，Apple Silicon，开发与原生验收设备为 Apple M4。应用采用本地 ad hoc 签名，未公证。

用户确认操作体验、找片选集换源、缓冲稳定性三方面都优化。沿用既有 AVFoundation / SwiftUI / Metal 架构，无新增第三方依赖。先确定范围和可检验行为，再分组实现、审查与回归，设计和计划见 `superpowers/specs/2026-09-27-player-v026-design.md`、`superpowers/plans/2026-09-27-player-v026.md`。

## 操作与反馈

- 新增 macOS“播放”菜单及快捷键说明。⌘P 播放暂停，⌥⌘← / → 前后10秒，⌘← / → 上下集。
- 点击控制栏时间或按 ⌘J 打开精确跳转，支持秒数、分:秒、时:分:秒和小数秒；输入必须有限且在片长范围内。保留当前播放意图，取消不改变进度。
- 倍速、内嵌字幕及音轨菜单标出当前选择，外部字幕显示文件名与选中标识。
- 播放菜单只对当前播放器窗口生效；片库、广告编辑、时间/帮助弹窗期间禁用相应命令，系统模态窗口另有执行层保护。

参考 VLC 的[精确时间跳转](https://docs.videolan.me/vlc-user/desktop/3.0/en/basic/playback.html)和 IINA 的[菜单快捷键优先级说明](https://docs.iina.io/interfaces/IINA.API.Input)。这些资料只用于交互设计，没有引入其播放器二进制或源代码。

## 选集与来源

- 选集面板拆成独立组件，显示上一集/下一集，当前集高亮并滚动定位；首末集、缺集和不属于当前播放记录的详情不能误跳。
- 换源分别显示搜索、读取集目、核对当前集媒体清单三个阶段；可取消，取消核对后保留候选。对取消后仍返回的异步结果再次校验，避免迟到结果切走影片。
- 切线路与换源保留最新的播放/暂停选择，核对期间发生的暂停或进度调整按提交时的最新状态处理。

## 播放稳定性

- 根据媒体准备状态、实际传输状态、播放意图及待完成定位统一计算提示，区分“正在准备媒体”“正在定位画面”“正在缓冲”。暂停状态不再因旧卡顿事件误显示缓冲。
- 连续等待15秒后提示手动重试或查找来源；不自动换源或循环重试。
- 终止失败会停止实际播放，关闭错误提示后仍保留失败状态；再次点击播放会重建媒体。重试保存原续播目标，包括0秒。
- 片尾事件检查当前媒体、定位请求及实际时间；片尾立即跳回中段时，旧回调不能触发下一集。正常结束及手动重播仍可用。
- 没有修改原12秒缓冲参数、系统网络/VPN设置或画质算法。

## 验证证据

核心测试、真实 AVPlayer 回归、原生界面及发布包校验分别记录，不将其中一种当作另一种的证据。

- `validation/v0.2.6/tests.log`：105项核心测试、16套件通过，覆盖原有功能及新增时间解析、加载/片尾策略。
- `episode-source-green.json`：11项 AppModel + 真实本地 AVPlayer 验证全部通过。异步来源为注入数据，明确模拟取消后迟到的搜索/详情/清单结果，没有真实片源联网。
- `playback-stability-headless.json`：13项通过，使用真实本地媒体、loopback延迟服务及明确标注的通知注入。包括正常EOF、真实EOF与定位竞态、暂停、失败与重试目标、连续等待15秒和换片清理。
- `playback-responsiveness.json`：8项已有响应回归通过，包括32轮连续快进、最新定位、取消定位、快速暂停播放与旧媒体隔离；已有 ControllerSmoke 和历史续播回归也通过。
- 独立代码审查发现并修复“关闭错误文案失去重试”和“零秒目标被当作无目标”两项状态问题；再补查重复失败事件不能覆盖已保存的目标。

原生发布应用已验证：片库播放菜单禁用、⌘J弹窗、非法 `1:60`、超过90秒片长的 `100`、小数秒 `20.5`、取消保持进度；弹窗内⌘P没有启动背景播放；⌘P和⌥⌘方向键响应；倍速从1×切到1.5×并显示正确勾选，再恢复1×；快捷键说明可读；F全屏隐藏侧栏、Esc恢复布局。

独立原生80集片库中，第75集首次打开即可见并高亮；第80集禁用下一集，第1集禁用上一集，⌘←可从第80集到79集。搜索/详情/清单核对均显示阶段，取消核对保留候选且迟到结果没有切走影片；重新选择后，在核对期间跳到31秒，换源完成仍是当前第75集、31秒、暂停。暂停时切线路也保持暂停和当前位置。

最终发布构建通过并重新启动，复验本地历史播放、⌘P暂停、⌘J定位45.55秒。签名严格校验、ZIP CRC、ZIP内可执行文件与应用的SHA256一致性均通过。结构化原生记录及发布摘要见同目录 `native-ui.json`、`release-manifest.json`。

## 验证范围

本轮不是新增媒体源或全站网络认证，没有重新进行所有片源的整集观看或大陆免VPN测试，也没有新增原生4K/AI4K能力。已有媒体与画质证据仍见此前验收记录。网络故障事件中的通知注入、真实loopback等待、真实EOF和实际用户界面操作在报告中区分。

独立验收夹具首次冷启动保持准备状态，按播放后就绪；未将这一现象直接归为产品缺陷。进一步用同一H.264文件在真实Controller/AppModel重复8轮准备后立即暂停和8轮暂停切线，共16项均就绪且保持3秒暂停；加入AVPlayerLayer的探针也通过。原生夹具后续暂停换源/换线通过。详见 `paused-h264-investigation.md`，未为未证实问题增加preroll。内嵌多音轨/字幕的勾选逻辑本轮经代码审查，未额外用原生多轨样本验收。

发布应用测试只使用已有本地90秒测试片，结束恢复其45.55秒暂停、1×、音量0.8、GPU增强至4K，并返回探索页；真实剧集记录未被播放或改动。长剧集测试使用独立应用标识与片库，避免写入用户的影视历史。
