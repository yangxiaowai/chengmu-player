# 映川 v0.2.7 验收记录

日期：2026-09-27。版本 0.2.7 / build 9，Apple Silicon，原生验收设备为 Apple M4。采用本地 ad hoc 签名，未公证。

## 问题与修复

用户反馈窗口和全屏的进度条等控件都不再自动隐藏。查明两个原因：全屏隐藏会触发 SeekBar 清理预览，重复的 `onHover(false)` 被误当成新操作，立即唤醒控制栏；窗口模式此前只有常驻底栏，策略也禁止窗口隐藏。

- 只有交互状态实际改变才重置闲置计时，重复清理不再唤醒控件。
- 两种模式共用3秒闲置策略。窗口底部控制栏叠在视频内并自动淡出；窗口顶部导航和选集布局保持原状。全屏顶部与底部控件一同隐藏。
- 暂停、缓冲、错误、拖动、控件悬停、菜单、弹窗或失焦仍保持控件可用。隐藏时同时关闭命中与无障碍访问。
- 仅全屏隐藏鼠标，窗口模式保留鼠标，避免影响顶部导航与选集操作。
- 外部字幕根据实际控制栏高度避让，避免错误提示或附加控件增加高度后与字幕重叠。

实施计划见 `superpowers/plans/2026-09-27-controls-autohide-fix.md`。没有修改媒体控制器、画质算法或来源配置。

## 验证

- `validation/v0.2.7/windowed-policy-red.log`：旧策略在窗口模式达到隐藏时限后仍返回不隐藏，预期失败。
- `control-visibility-red.json`：对 v0.2.6 基线运行真实 PlayerPresentationController，12项中6项失败。全屏发生隐藏后立刻重新显示，窗口不发生隐藏。
- `control-visibility-green.json`：同样12项全部通过，覆盖两种模式的真实 Timer、发布状态与预览清理回调、重复 inactive 回调、真实交互保持、离开后的新计时及暂停唤醒。夹具使用屏外 AppKit 窗口与测试专用活跃标记，不控制用户 UI，不注入输入事件。
- `tests.log`：104项核心测试、16套件通过。旧版“窗口应一直显示”的单项断言已被新的两模式控制器回归替代。
- `release-build.log`：最终源码 Release 构建成功。独立只读审查未发现剩余实质问题。

实际发布应用用已有30秒本地测试片完成：窗口底部控件在播放闲置后隐藏；全屏画面只保留视频，控件在无障碍树中也消失；左方向键快退立即唤醒控件；暂停超过3秒仍显示；拖动进度后显示00:08缩略图并保持暂停；单击画面继续播放并离开预览区域后，控件再次自动隐藏。硬字幕在隐藏前后可见。观察期间没有只移动鼠标的独立工具动作，未把点击移动验证称作单独的鼠标移动唤醒验证。软字幕避让逻辑经过代码审查和构建，本轮没有单独的外部字幕样本实机验收。

实机操作记录见 `native-ui.json`。发布包校验见 `release-manifest.json`，包括严格签名检查、ZIP CRC、包内程序与当前应用的SHA256一致性。
