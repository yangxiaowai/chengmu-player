# v0.3.5 修复质量改进

日期：2026-09-29。设备：Apple M4 / macOS 27.0。延续用户对实时修复、减轻噪点、同帧对照和字幕保留的要求。本轮源码与 v0.3.4 已有工作共同构建，没有重写原有播放器或媒体目录。

## 实际改动

- 放大器只把**对比度判定**从线性亮度转到 `sRGB OETF(Y)` 近似感知亮度，门控为 0.03…0.14；保持线性光插值、方向一致性判断、2×2 邻域包络夹紧。这样不会让相同码值幅度的噪点在亮部获得明显更强的细节权重。
- 空间输出、广告柔化底图与补丁、运动插帧输出统一使用 `rgb10a2Unorm`，不再经过旧版 `bgra8Unorm` 输出量化。每像素仍为 4 字节；按 sRGB 编码及显式色彩标签交给浮点显示层，不改为 HDR。
- 保留时域默认强度 0.75。固定强度扫参显示：0.5 在三种影片退化样本的展示 PSNR 仅提高 0.017–0.035 dB，但强 RGB 噪声夹具的 MSE 恶化 46.9%，不能无条件替换。
- 模式说明补充弱纹理可能稍柔和；原片及同帧分屏保留。HDR、杜比视界继续原生呈现。

方案和文献：[实施范围](superpowers/plans/2026-09-29-repair-quality.md)、[CDEF/引导滤波/RCAS 调研](research/content-adaptive-postfilter-2026-09-29.md)。这些额外后处理尚未证明本机端到端收益，因此未默认叠加。

## 画质对照

使用相同输入、尺寸、随机种子、参考图和 GPU 回读，先跑旧实现再跑最终实现。精度测试旧版13/19、新版19/19；缩放质量旧版32/34、新版34/34，失败恰为目标问题。

| 指标 | 旧版 | 新版 | 范围 |
| --- | ---: | ---: | --- |
| 10-bit SDR 渐变普通输出的独立灰阶 | 256 | 877 | 输入本身877级，单行浮点回读 |
| 普通渐变输出码值 RMS 误差 | 0.001131 | 0.000268 | 比直接解码图，约减少76.3% |
| 渐变放大输出独立灰阶 | 256 | 1024 | 2倍缩放；不表示恢复原片信息 |
| 亮部平区原始噪声 MSE / 双线性 | 1.1547 | 1.0110 | 灰192±8，缩放器压力样本 |
| 亮部平区时域后噪声 MSE / 双线性 | 1.0438 | 0.9962 | 相同默认时域后，残噪约下降4.6% |
| 轻噪声影片静帧 PSNR | 32.3464 dB | 32.3611 dB | 480×200→960×400，同frame24 |
| 压缩影片静帧 PSNR | 30.8706 dB | 30.8836 dB | 同尺寸同帧参考 |
| 强阶跃10%–90%过渡宽度 | 2 px | 2 px | 无新增过冲，B-spline参考3 px |

**不是所有指标都更好。** 灰64±8的时域后噪声比值由1.0059升至1.0328；弱对比纹理调制度有小幅下降。新格式和新门控合并后的真实影片静帧改善只有0.013–0.015 dB，视觉差异细微。本轮没有证明整部影片显著提升、原生4K细节恢复、实际显示10bit或稳定60fps。

[可切换同帧对照](validation/v0.3.5/画质对照.html)展示程序原始PNG；没有额外生成、美化或差异倍增。PNG为8位展示，不能用它展示10bit渐变优势，后者以浮点数值为证。影片两例仅测试缩放；合成亮部示例才包含相同时域前处理。

旧新JSON：[旧精度](validation/v0.3.5/repair-precision-red-full.json)、[新精度](validation/v0.3.5/repair-precision-green.json)、[旧缩放](validation/v0.3.5/detail-red.json)、[新缩放](validation/v0.3.5/detail-green.json)。固定强度三类影片各96帧及字幕/运动夹具见[扫参](validation/v0.3.5/strength-sweep.md)。初步只改门控的A03/A06比较与源码哈希见[候选记录](validation/v0.3.5/detail-gate/README.md)，与最终10bit存储结果分开。

## 回归与运行成本

GPU任务独占串行，计时阶段不并行构建。最终已完成：

- 核心159测试/20套件通过。
- 精度19/19：有效10bit YUV渐变、独立RGB色块、sRGB往返、alpha=1。
- 缩放34/34：暗中亮噪声、15组弱纹理、真实静帧方向与尺寸、无过冲及完成GPU计时。
- 流式处理35/35：时域首帧/历史、切换/拖动、尺寸、4K输出、字幕保护区和柔化选区外像素不变。
- HDR/原生路由32/32：HDR保留、色彩未知保护、输出稳定性及异步生命周期。
- 插帧16/16：60Hz时间格点、运动生成内容、独立输出纹理、切镜/换源复位；不是屏幕稳定60fps证据。
- 1080p真实AVPlayer短时播放14/14：24fps源，流式修复输出3840×2160，完整空间处理采样均值23.78ms；约3.10秒窗口完成75帧（24.20帧/媒体秒）。无可见屏幕，不是长期播放、物理刷新或主观音画同步测试。

缩放器单独1080p→4K、预热后60帧：旧平均3.082ms/P95 3.181ms，新平均3.077ms/P95 3.151ms。小差异视为本次采样波动；可说没有测到明显额外成本，不能外推成4K60整链能力。

## 发布和审查边界

独立代码审查未发现本轮可确认缺陷；检查了同格式blit、颜色契约、输出所有权及alpha。RGB10A2的alpha只有2位，适用于当前不透明YCbCr视频链，不能作为通用透明图像处理保证。精度测试只直接覆盖普通输出与DetailScaler，不宣称Apple时域、AI、FRC模型内部全链无损。

对照页在Codex内置浏览器进行了布局查看、样本选择及键盘旧新切换；图片加载正常、没有控制台错误。Mac锁屏时指针点击没有改变页面状态，未把这种环境下的点击算作通过，未验证原生播放器可见UI。

应用版本0.3.5 / build17已安装到 `dist/映川.app`；原入口的v0.3.3/build15已备份到 `dist/历史版本/映川-v0.3.3-build15-2.app`。本次安装时没有运行中的旧副本，未强制中止播放。发布位置、签名、ZIP校验见[发布清单](validation/v0.3.5/release-manifest.json)。未修改用户片库数据。
