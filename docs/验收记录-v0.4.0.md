# 澄幕 v0.4.0 / build23

日期：2026-10-26。源码从 v0.3.9 增量更新。本版完成媒体画质读取与全部主要页面重设计，不变更修复算法或宣称新增杜比/4K60 能力。

## 用户界面

探索、搜索、详情、待看、历史、媒体来源、画质设置与播放控制统一为炭黑背景、蓝色操作。删除日常界面中的抽样、首集参数、轨道读取等开发文案；连接与处理详情默认收起。封面加载失败时显示澄幕原创文字封面。详情以播放、来源、线路和选集为主要操作。

用户随后反馈“画质信息还是不能看到”。真实 build22 窗口与代码核对发现：卡片只有 `.ready` 状态才有标签，且自动读取只尝试前两个来源。build23 改为所有卡片始终显示分辨率或等待/识别中/暂未获取状态，已有帧率直接显示；详情未取得帧率时明确显示“帧率未知”。同作品一个来源失败后顺序尝试后续来源，成功即停止；卡片右键可优先更新画质，手动刷新会绕过后续来源的旧失败缓存。

界面参考与来源边界见 [设计说明](design/catalog-v0.4.md)。没有取得 B 站二进制或源码，没有进行反汇编。官方客户端下载链接实际 GET/HEAD 返回 HTTP 403，改用官方展示图研究可观察布局。

## 媒体读取策略

AVFoundation 先尝试读取轨道；普通 HLS 必要时使用无界面的静音播放器准备项目，仍无尺寸时读取第一帧。最多同时两项、排队48项；成功缓存15分钟，失败60秒，均仅限会话。单次媒体识别8秒预算，目录详情请求有独立网络时限，不承诺整个来源流程8秒。播放和本机性能检测取消后台识别；暂停自动识别后仍可手动更新。

请求共享相同媒体 URL 的识别工作；手动请求可提升排队位置，队列满时让出最后一项后台工作。取消令牌避免旧结果回写。刷新同步已有来源/线路结果，复用结果保留原读取时间。失败缓存与排队状态分开存储，防止同时查看来源和线路时重复访问同一个失败链接。

分辨率来自实际读取，宽银幕/竖屏显示真实尺寸，不仅凭片名或短边标为4K。HLS 自适应选择可能与正式播放不同；一个集目的参数不代表整季、所有码率或主观细节质量。格式未知/网络失败仍允许正常选源播放。

## 验证及实际边界

- 核心：168 项、21 个套件通过，含6项新媒体参数测试。见 [日志](validation/v0.4.0/core-tests.log)。
- 请求协调：23 项通过，覆盖并发上限、队列边界、原集读取、同 URL 合并、缓存期限、强制刷新、取消竞态、跨线路失败冷却、第三来源回退与恢复后的手动重试。修复前失败日志与最终 [JSON](validation/v0.4.0/quality-queue-final.json) 分开保留。
- 媒体集成：15 项局部 HTTP/MP4/HLS 检查通过，含旋转、虚假4K文件名、无效/纯音频、挂起连接超时与取消后实际断开。见 [报告](validation/v0.4.0/backend-hls-local/backend-media-quality.json)。
- 真实网络：Mux 公开 HLS 超时；魔都《星际穿越》指定来源的一个集目读到1920×1080、avc1、估算2.78Mbps，约5.04秒，未获取帧率。失败与成功均保留在 [原始记录](validation/v0.4.0/backend-live-sample-hls-fallback.json)。没有据此认证片源身份、版权、整集稳定性或全国免VPN可用性。
- 控制栏：12 项真实控制器计时回归通过；[记录](validation/v0.4.0/control-visibility.json)明确不是鼠标/全屏物理交互验收。选集/换源11项通过，未发网络请求。
- 原生渲染与模型接线：18 项通过，包含1280与1040窗口、搜索、详情、待看、历史、来源、画质页及播放控制9张图片。见 [报告](validation/v0.4.0/ui-consumer/quality-discovery.json)。注入的片名、来源与画质是演示数据，封面部分来自公开目录，只用于布局预览；说明放在报告中，不放进产品界面。
- build22 真实应用额外打开首页，确认真实目录封面与部分画质标签，点击来源和画质导航成功；用户开始自行操作后停止自动化。`live-home.png`是当时真实窗口，不能用它证明随后 build23 状态标签已安装。离屏播放器图片仅用于控件布局，视频图层不可据此验收。

用户授权正常退出后，已从应用菜单退出 build22 并安装 build23；旧版保存在 `dist/历史版本/澄幕-v0.4.0-build22.app`。确认本机版本、签名和可执行程序与已发布归档一致。重新打开的真实首页已显示1920×808、1080×606、720P和1080P等读取结果，以及“等待识别”“识别中”“暂未获取”状态；对应集目的帧率未提供，未填写假值。实际画面见 [build23截图](validation/v0.4.0/ui-consumer/live-build23.png)，可访问性读数见 [记录](validation/v0.4.0/ui-consumer/live-build23-ax.txt)。此项不扩展为整集播放或所有片源可读取的证明。
