# 澄幕 v0.4.2 / build25

日期：2026-10-26。修复用户指出的“单集看完即整部剧看完”错误，不更换播放或图像处理引擎。

## 根因与实现

旧版`WatchRecord.isCompleted`只判断当前媒体position/duration>=95%，被`historyRecords`和记录页直接作为作品完成条件，导致最新一集中途完成后，整部作品被隐藏并提示重新观看。

现在`isEpisodeCompleted`只负责单集阈值；`isCompleted`还校验保存的`playbackContext`、当前选集是否为最后一集、其他线路是否存在后续集。明显为剧集但仅一集、上下文丢失/损坏、集号式旧记录均保守保留。电影和无季集特征的旧单文件记录沿用单片进度。没有修改Codable历史字段或清空既有数据。

默认作品视图先聚合最新记录，再按作品完成筛选，避免把旧未完集重新冒出来；全部剧集视图按单集阈值筛选。中间集完成标为“本集已看完”，真正末集完成标为“全部已看完”，时间明确标注“本集已看”。当前保存列表不等于来源已官方完结；不猜测跨季进度。

续看目标只来自同一可信线路的下一项，数字集号必须连续；编号未知或有缺口时不跨越，旧记录不猜下一集。下一集已保存进度时沿用其ID/URL/集名核验后的独立进度；未看过从0开始。完整作品重新观看从当前线路第一集开始，全部剧集视图重看所选集。选择计算本身不写历史，实际播放仍使用原有保存链路。

核心首轮6个测试中有6项断言真实失败，覆盖中间集、短线路、旧/坏上下文。新增纯数字旧集名断言也先失败再修复。新API首轮尚未存在的编译失败单独保留；集成驱动曾访问私有url，已改用AVURLAsset；整数字面量范围曾被推断为Optional使fixture路径错误，显式Int后重新运行通过。这些驱动问题不冒充生产行为缺陷。

集成实际打开第二个本地视频，恢复其12秒进度，维持暂停，并验证第一集历史仍存在。三张原生位图展示[中间集续看](validation/v0.4.2/ui/continue-next-episode.png)、[末集已看完](validation/v0.4.2/ui/completed-series.png)和[按单集查看](validation/v0.4.2/ui/individual-episodes.png)，已目视检查没有按钮重叠。它们是演示数据和离屏渲染，不等于物理鼠标点击、全屏或完整网络影片验证。

构建、安装、归档、签名与GitHub核对以发行清单和后续回执为准。

独立复核指出未知集号相邻不代表连续、较长备用线路未知编号不能被忽略，新增两个断言真实失败后修复：未建立数字连续性时不提供自动下一集，任何较长备用选集列表都会保守阻止作品完成。

同一复核者再次静态审阅两项修复，确认已解决，未发现剩余实质问题；运行测试由主任务单独执行。

已通过系统正常退出旧版并安装build25，旧版备份在`dist/历史版本/澄幕-v0.4.1-build24.app`。正式版真实记录页确认：当前未完成作品仍在未看完中，另一作品末集完成在全部记录中标为全部已看完，已完成的中间集在全部剧集视图标为本集已看完；未启动新影片、未修改进度，查看后恢复默认筛选。原始用户记录截图仅留本机，公开回执只保留[检查状态](validation/v0.4.2/native-history-ui.json)。

归档CRC、解压后的版本、签名和可执行SHA-256与已安装版一致；见[发行清单](validation/v0.4.2/release-manifest.json)。本地签名，未Apple公证。
