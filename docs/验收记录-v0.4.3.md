# 澄幕 v0.4.3 / build26

日期：2026-10-27（2026-10-26开始开发）。新增选源时的媒体HTTP响应延时展示，不更换播放、HDR或画质处理引擎。

## 响应口径与界面

`MediaResponseProbe`对已取得的媒体URL发起HTTP HEAD请求，记录从创建该次请求到收到有效响应头的耗时，包含本次连接和重定向等开销；不用ICMP、不计带宽或起播时长。单次探针至多约3秒，目录加载和画质读取分别另计。关闭探针缓存和Cookie，跟随系统网络设置。拒绝无效/含账户密码的URL及非法重定向；HEAD不受支持或被限流时记为未获取，不阻止正常播放。

选择界面的来源卡片、线路卡片同时显示画质与毫秒数；播放侧栏的线路菜单和其他片源展示缓存数据。悬停说明方法与检测时间。可更新画质与延时重新检查；不会为了检测禁用来源选择。播放/性能检测取消后台请求，未测项明确提示暂停或尚未检测。

来源页原`elapsedMS`是多阶段检查总耗时，未用它冒充媒体延时。一个来源/线路的一集结果不代表全部集数。

## 协调与边界

沿用最多2任务、48排队、同URL共享、15分钟会话缓存、手动优先、失败冷却与令牌取消。HTTP响应独立于画质状态：HEAD失败仍继续AVFoundation元数据读取；元数据失败保留已取得响应。

响应早于画质完成，过期时间可能不同，已验证响应过期时即使画质尚在缓存也能刷新。独立URL测量缓存保留flightID，晚加入同一请求的来源/线路可重放已完成的响应，避免永远停在检测中。缓存限制256项，活动测量结果不被清理；旧取消任务不得回写。

探索实现曾尝试GET正文/响应头，但本机URLSession可能等待正文才交付，导致“仅响应头不发正文”场景超时；最终改用语义明确的HEAD，不将此前GET失败记录计入HEAD成功。HEAD可以返回有效响应但正文并不可播，画质与播放状态另行呈现。
