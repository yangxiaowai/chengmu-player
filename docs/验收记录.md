# 映川 v0.1 验收记录

日期：2026-09-27。本次交付为可运行的 Mac 原生首版，包含源码、Release 应用、构建脚本与研究记录。按已确认需求完成设计后编码，仍有明确未完成目标，不能将首版交付等同于所有影片的真正 4K。

## 环境与复现

- 实测设备：Apple M4、16GB 内存、macOS 27；应用为 arm64 本机构建。内置屏幕 3024×1964，不能呈现完整 UHD 物理像素。
- 程序：`dist/映川.app`；SwiftUI/AppKit、AVFoundation、Core Image/Metal、VideoToolbox。无第三方运行时依赖，未将 FFmpeg 或外部播放器打包进去。
- 构建：`bash scripts/build-app.sh release`。本地 ad hoc 签名；未进行 Apple Developer ID 公证或其他 Mac 实机验证。
- 测试：`bash scripts/swift.sh test`，29 个测试、5 个套件通过。覆盖来源解析、真实详情标题校验、同季同集匹配、HLS清单、历史版本与集目上下文、字幕、尺寸和帧预算。日志：`validation/tests-final.log`。
- 工具链包装脚本只修正项目 `.build` 中的 SwiftPM 接口查找，不修改系统工具链。构建日志中的两个缺失 CLT 搜索路径警告不影响此次成功链接。

## 媒体来源

两个默认 HTTPS 目录已经接入应用，可自行检索、选季选集和播放。用户无需先提供自己的影片。目录中分别出现三剧 15 季、164 集，实际基础验证范围如下。

| 作品 | 季集数 | 主源清单 |
| --- | --- | --- |
| 怪奇物语 | 8 / 9 / 8 / 9 / 8，共42集 | 全部42条符合媒体清单结构 |
| 绝命毒师 | 7 / 13 / 13 / 13 / 16，共62集 | 全部62条符合媒体清单结构 |
| 火线 | 13 / 12 / 12 / 13 / 10，共60集 | 全部60条符合媒体清单结构 |

证据：`validation/source-report.json`、`validation/backup-source-probe.json`。主源164条清单验证包含清单结束标记、媒体分片及声明时长；备用源是目录覆盖与4个首分片探测，未将备用源164集逐一解码。多个清单的声明分辨率与真实分片不一致，所以播放器显示解码帧的尺寸。

45个代表样本覆盖每季首/中/末集，各解码约2秒。42个快速跳转成功；《怪奇物语》第五季3个样本快速跳转输出零帧，改为输入后准确跳转才成功。原失败记录保留，没有把零帧、退出码0当成成功。成功尝试无解码错误，实测1080p/1916×1080/720p及AAC双声道。证据：`validation/representative-decode.json`。

《火线》的宽泛搜索首页会混入同名电影，现已对明确的“火线”检索和发现页使用一次“火线第”查询；实测每个默认目录均返回五季。诊断模式要求指定目录ID精确命中。早期诊断误选同名电影的记录留在 `validation/the-wire-wrong-search-result.json`，排除在剧集验收之外。

跨源入口位于播放器右侧“查找其他片源”。先核对明确季名，再核对详情实际标题和集名/编号，检查HLS清单后切换；进度限制在新版本时长内。资源剪辑不同可能需要手动对齐，候选不在解码前冒充“更高清”。

## 流式增强与实播

GPU模式逐帧执行去噪、等比例Lanczos缩放与锐化，并实际生成UHD边界内的纹理；AVPlayer提供音频时间轴，队列有界。seek/切集后旧处理结果作废，持续超预算、未知方向或未支持的HDR处理会说明原因并回到原片。软字幕最后叠加；烧录在视频里的字幕属于原始画面。

Apple AI模式调用系统实际低延迟超分处理器并查询可用倍率。本机720p可用1.5倍到1080p；1080p输入不支持的情况显示原因。未通过先缩小再放大伪造AI 4K。

实播结果由本次各JSON记录及后续汇总段说明。诊断播放静音，所以没有主观听音同步验收；呈现时间戳不能单独证明主观音画同步、修复质量或所有画面没有伪影。系统AV掉帧/卡顿指标与程序“忙碌跳过”计数含义不同，后者也包含重复轮询遇到处理忙碌的次数，不能相互替代。

### 实测结果

| 场景 | 实际结果 |
| --- | --- |
| 怪奇物语第一季连续基线 | 运行1801秒，影片进度1797.8秒；1920×1080→3840×2160，呈现43234帧；1800次采样中1798次有增强，前2次起播；0增强回退、0 AV卡顿/掉帧 |
| 怪奇物语第五季定位后播放 | 从约60秒起播，运行90秒，最终146.8秒；2030增强呈现帧；0 AV卡顿/掉帧 |
| 绝命毒师第一季定位后播放 | 从约120秒起播，运行90秒，最终205.2秒；1916×1080→3832×2160，2038增强呈现帧；0 AV卡顿/掉帧 |
| 火线第二季真实AI播放 | 从约90秒起播，运行91秒，最终176.2秒；1280×720→1920×1080，2146 AI呈现帧；0 AV卡顿/掉帧 |
| Release跨源及控制操作 | 180秒诊断窗口内完成切源、快进、倍速、暂停、历史恢复、下一集；包含人为交互，不用于连续性能结论 |

原始记录：`validation/playback-summary.json` 及其引用的5个实播JSON。30分钟运行期间有并行构建和第二个短播放实例，不是空载实验。每秒采样的1080p→4K处理耗时中位16.86ms、P95约21.79ms，不能当作每一帧的完整分布。尾段约10分钟20次RSS采样为94.1–106.0MiB，非全程峰值，也不等同于所有GPU/系统内存占用；见 `streaming-memory-tail.json`。

最终Release另外完成每种模式240张合成720p帧：GPU清晰增强均值2.08ms、GPU4K均值12.23ms、AppleAI均值4.23ms；AI首帧113.18ms、热身后均值3.77ms。输出像素抽样非全黑，90度旋转处理尺寸720×1280检查通过。合成基准不替代真实视频质量或同步验证；见 `gpu-benchmark-final.json`。

## 原生界面操作验收

通过实际UI依次完成：绝命毒师第一季主源查找非凡备用源、同集切换与约205秒位置恢复、备用源画面及3832×2160增强确认、快进10秒、1.5倍速、暂停于241.945秒、返回历史再恢复该位置及7集上下文、下一集进入第二集。火线第二季AI播放画面也已目视检查。见 `validation/ui-acceptance.json`。切换操作过程的 `source-switch-app.json` 包含人为暂停、跳转和切集，不能作为连续播放性能测试。

## 修复与审阅

独立代码审阅发现并修复：历史缺少季集上下文；匹配失败提前切换线路；数组序号形成不稳定集目ID；未应用旋转信息；详情标题校验误用搜索标题；方向元数据失败在seek后丢失回退原因。原发现的修复已复审。HLS不提供普通轨道时的增强起播问题经第五季实播复测，已恢复增强。

## 仍未完成的目标

- 未找到并实际验证三剧原生3840×2160来源；没有实现通用1080p→4K的AI重建。GPU输出4K不等于新增真实细节或原生4K。
- 没有逐集看完164集，也未视觉确认所有条目的剧情身份、完整性及跨日稳定性。网络来源可能改变，供应许可未核验。
- 自动选择“最好画质”的全自动排序尚未完成；目前提供跨来源候选与实际播放尺寸供比较，不能只凭清单标签可靠判断细节、码率和版本质量。
- MKV全格式兼容、完整ASS样式/动画、HDR增强、多设备同步尚未实现；视频格式支持以当前AVFoundation实际解码能力为准。
- 外部字幕解析和时轴有单元测试，全部轨道/样式及主观字幕同步并未全面实机验收。未做全屏外接4K屏、Intel Mac或其他设备验证。

## 构建对应关系

`validation/release-manifest.json` 记录最终Release可执行文件与源码SHA-256，原生跨源/历史/倍速/切集操作使用相同Release可执行文件。30分钟基线在较早调试构建上开始，期间未替换该运行进程；随后修正HLS方向回退、实际详情标题校验和火线检索，并另做短实播及最终Release操作验收。因此30分钟结果不冒称最终二进制已连续验证30分钟。
